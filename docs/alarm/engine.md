# 告警引擎（判据执行侧）

> **一句话**：本目录实现契约 §1.5 / §1.5.1-1.5.4 / §1.8 的**判定逻辑**，
> 把「策略配置」和「时间序列数据」变成「要不要告警」。
>
> ⚠️ **它不在 HTTP 链路上**。管理面（`App\Controller`）不执行判定，
> 引擎也不暴露端点。两者通过**策略数据**和**采样数据**解耦。
> 引擎可以独立部署成常驻进程或定时任务。

---

## 1. 边界：谁做什么

| | 管理面（本项目其余部分） | 引擎（`App\Engine`） |
| --- | --- | --- |
| 策略 CRUD、校验、存储 | ✅ | ❌ |
| 指标字典、预置模板 | ✅ | 只读消费 |
| 通知模板、告警历史 | ✅ | ❌ |
| **基线计算、判据求值** | ❌ | ✅ |
| **心跳读取与静默判定** | ❌ | ✅ |
| 写入心跳 | ❌ | ❌ ← **采集侧的活** |
| 实际发送通知 | ❌ | ❌ ← 通知服务的活 |

**刻意留白的三块**及原因：
1. **不写心跳** —— 心跳由采集侧（agent）上报。管理面写心跳等于自己给自己盖章。
2. **不发通知** —— 通知要走去重、抑制风暴、多通道降级，是独立服务的事。
3. **不落告警历史** —— 告警历史表的写入方应该是引擎产出侧，且要考虑
   「同一次故障不重复落库」的去重语义。本项目只定义表结构。

## 2. 依赖的两个接口

```php
interface SampleRepository {
    /** 取「窗口起点在 [from, to] 内」的采样，升序。闭区间。 */
    public function fetch(string $ns, string $name, int $period, int $fromTs, int $toTs): array;
}

interface HeartbeatRepository {
    /** 最后一次心跳时间（秒）。从未上报返回 null —— 不是 0。 */
    public function lastSeenAt(int $targetType, int $targetId): ?int;
}
```

**为什么是接口**：引擎本就该独立部署。时序库（InfluxDB / VictoriaMetrics）、
本项目的 MySQL、自研采集器都能实现 `SampleRepository`，引擎不选边。

**为什么是闭区间**：环比取「前 N 个周期」时，相邻窗口的**边界点必须能同时被两个
窗口引用**。用左闭右开会少一个点，而且不报错——只是基线算错一点点，极难发现。

## 3. 语义定义（契约只给了字段，这���是实现细节）

### 3.1 单点求值

`period=p` ⇒ 每个采样点代表 `[t-p×60, t)` 这个窗口的统计值。
`period=5` 时，`t` 时刻的点是最近 5 分钟的聚合。

### 3.2 基线定位

| baselineType | 基线位置 |
| --- | --- |
| `period` | 往前 `baselineCount` 个 period 窗口的那**一个**窗口 |
| `day` | 前 1 天**同一时刻**的窗口 |
| `week` | 前 1 周**同一时刻**的窗口 |

基线是**单个窗口**而非 N 个窗口的均值 —— 契约 §1.5.3 明确「`n=1` 表示与前一个
周期比」，若取 N 个窗口的均值，`n=1` 会变成「和前 2 个窗口的均值比」。

### 3.3 连续性

`continuity=N` ⇒ 条件在最近 N 个**评估时刻**上都成立。
评估时刻 = `now, now-p, ..., now-(N-1)p`。

> ⚠️ **每个评估时刻用自己���基线**。基线随时间平移：用「最新时刻的基线」
> 回测历史评估点是错的——昨天 9:00 的基线不是今天 9:00 的基线。
> 代价是 N 次求值、N 组读取。**用正确性换性能**，在告警系统里划算。
> 回归测试 `testRelativeContinuityUsesPerTimestampBaseline` 专门钉死这一点：
> 它构造的数据让「正确实现」和「偷懒实现」给出**相反**结论。

## 4. 契约 §1.5.4 的三条边界（实现时最容易错的三处）

| 情况 | 判定 | 实现细节 |
| --- | --- | --- |
| `baseline == 0` | 不命中 | PHP 8 里除以 0 抛 `DivisionByZeroError`，会让整次求值挂掉，必须提前拦 |
| 基线窗口无数据 | 不命中 | 退化成 `baseline=0` 会让 deviation 变 ±∞，`∞ > 30` 为真 → **每次都告警**，比不告警更糟 |
| `baseline < 0` | `abs(value-baseline)/abs(baseline)` | 直接除会**符号翻转** |

第三条的具体危害（`value=-20`、`baseline=-100`）：

```
错误：(v-b)/b  = 80 / -100 = -0.8  → 「比基线跌了 80%」  ← 说反了
正确：(v-b)/|b| = 80 / 100 = +0.8  → 「比基线涨了 80%」
```

配上 `operator='<'` 判「跌超 30%」时，错误实现会**持续误报**：
明明是从 -100 涨到 -20（好转），却判成「跌了 80%」。

### 4.1 浮点近似零也要拦

用 `abs($baseline) < 1e-12` 而不是 `=== 0.0`。
均值在浮点下可能算出 `1e-17` 而不是精确 `0`，
只判 `=== 0.0` 的话 deviation 会是 `1e19` —— 一个巨大的正数，`> 30` 成立 → 每次都告警。

### 4.2 非有限值在构造时就拒

`Sample` 构造时拒绝 `NAN` / `INF`。因为 `NAN > x` **恒为 false**——
一个 NaN 混进基线均值会让条件**永不触发**，且没有任何报错。

## 5. ⚠️ 契约的一处更正（初稿写错了）

契约 §1.5.4 初稿写：

> 例如 `compareMode=relative, operator=<, threshold=30` 表示「相对基线跌超 30%」

**这是错的。** 按同一节的公式 `deviation = (value-baseline)/baseline × 100%`：

```
value=80, baseline=100  →  deviation = -20%
-20 < 30  →  true      ← 跌 1% 也会命中！
```

任何幅度的小幅下跌都会触发，而用户以为只报大跌。
**要表达「跌超 30%」必须写 `threshold = -30`。**

契约已更正为带符号的对照表。**实现方请以更正后的表格为准。**
回归测试 `relativeProvider` 里有一条 `'跌 20% < 30（错配，正阈值）' => true`
专门把这个坑钉住——它证明正阈值确实会误报，而不是断言它不该发生。

## 6. 采集静默（F 类）的关键设计

```
命中 ⟺ (now - 最后心跳) > targetFreshnessMinutes × 60
```

### 6.1 从未上报**判命中**

一个刚创建、采集侧还没上报过任何心跳的目标，`lastSeenAt` 返回 `null`。
两种选择：

- 判「不命中」→ 采集侧完全没接上时**永远不告警**，回到 F 类要解决的原问题
- 判「命中」→ 刚建策略就报一条「从未上报」，噪音但方向对

**取命中。** 理由：F 类缺口的核心危害是「所有故障都不被发现，**且系统看起来一切正常**」。
「看起来一切正常」正是必须消除的状态。首次心跳到达后行为自然转为正常。

### 6.2 `null` 与 `0` 必须区分

`lastSeenAt` 返回 `null`（从未上报）≠ 返回 `0`（1970 年上报过）。
用 0 兜底会让「从未接入」显示成「静默 5610 万年」，把排查引向完全错误的方向。
接口注释和测试桩都专门强调了这一点。

### 6.3 缺 `targetFreshnessMinutes` 必须抛异常

契约要求 `policyType=5` 时该字段必填且 `5 <= n <= 10080`。
若当成「永不安静」放过去，配置缺失就变成**永不发告警**——最坏的静默失效形式。

## 7. 可观测性：每个 Verdict 都带「为什么」

```php
final class Verdict {
    public readonly bool  $hit;
    public readonly string $reason;          // 「相对昨日同期基线50 偏离 +300.00% > 50.00%」
    public readonly ?float $value;           // 当前值
    public readonly ?float $baseline;        // 实际采用的基线
    public readonly ?float $deviationPercent; // 相对模式下的偏离（带符号）
}
```

**为什么必须带原因**：引擎出问题时（该报不报），排查的第一句话永远是「为什么」。
只返回 `bool` 的话，运维只能翻日志、猜基线算成了多少。

`PolicyVerdict` 进一步带**每条条件**的明细。`conditionLogic=AND` 时
「整体没命中」本身没有诊断价值——用户需要知道是哪一条拖后腿。

### 7.1 非法输入一律抛出，不静默降级

| 情况 | 静默降级的后果 |
| --- | --- |
| 未知 `operator` | `match` 兜底 `false` → 条件**永不触发** |
| 未知 `baselineType` | 退化成「基线=当前值」→ deviation=0 → **永不触发** |
| 未知 `policyType` 走错分支 | 静默条件得到「无数据点」误导结果 |

**静默失效比报错难查一百倍。** 枚举已由 `ConditionValidator` 校验过，
到这里出现非法值说明数据绕过了校验——属于必须暴露的情况。

## 8. 测试：68 条

| 文件 | 条数 | 覆盖 |
| --- | --- | --- |
| `ConditionEvaluatorRelativeTest` | 30 | 契约 §1.5.4 三条边界 + 绝对判据 + 非法算子 |
| `PolicyEvaluatorTimeAxisTest` | 15 | period/continuity/baselineType 时间对齐 |
| `SilenceEvaluatorTest` | 12 | 心跳静默 + null/0 区分 + 目标隔离 |
| `PolicyDecisionMakerTest` | 11 | AND/OR + 等级取值 + 停用短路 + 静默分支 |

**用「让两种实现给出相反答案」的数据做负对照**，而不只是断言 happy path。
典型的两个：
- `testNegativeBaselineDoesNotFalsePositiveOnLessThan` —— 负基线 + `<` 必须不命中
- `testRelativeContinuityUsesPerTimestampBaseline` —— 每时刻用自己基线 vs 偷懒用最新基线

## 9. 还没做的

- **通知抑制**：告警风暴时的收敛、依赖关系抑制、值班轮转
- **告警历史落库**：去重语义（同一次故障不重复落库）由谁定义
- **多对象并发求值**：`objectType` 展开后的批量评估与并发
- **表达式语言**：契约目前只支持「单值 vs 阈值」，不支持 `a AND b > 80` 这类复合表达式

这些都需要产品决策或独立设计，不该在实现阶段顺手加。
